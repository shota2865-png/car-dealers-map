## 4. あなたがやること（順番どおりに。合計 40 分）

本体のときと同じ作業を、名前だけ変えて 1 回やります。**一番大事なのは 2 の「別プロジェクト」**です。
同じ Google Cloud プロジェクトを使うと、YouTube API のクォータ（1 日 10,000）を 2 チャンネルで分け合うことになり、
1 日 2 本 + Shorts 6 本 = 約 14,000 で必ず溢れます。

1. **YouTube でチャンネルを作る**（5 分）
   YouTube → 右上のアイコン → 設定 → 「チャンネルを追加または管理する」→ 「チャンネルを作成」。
   名前は 2 節から。作ったら左メニューの「カスタマイズ」で説明文だけ入れておく（後で直せる）。
   Studio → 設定 → チャンネル → 機能の利用資格 で **電話番号の確認**をしておく（15 分超の動画と自作サムネに要る）。
2. **Google Cloud で新しいプロジェクトを作る**（10 分）
   [console.cloud.google.com](https://console.cloud.google.com/) → 上のプロジェクト名 → 「新しいプロジェクト」→ 名前は `psych-uploader` など。
   そのプロジェクトで「API とサービス → ライブラリ」から **YouTube Data API v3** と **YouTube Analytics API** を有効化。
   「OAuth 同意画面」→ 外部 → アプリ名・メール・ホームページ（本体と同じ `https://shota2865-png.github.io/car-dealers-map/oyasumi/` でよい）→ 公開ステータスを**本番環境**に。
   「認証情報 → OAuth クライアント ID」→ 種類 **ウェブアプリケーション**、承認済みリダイレクト URI に `http://localhost` → クライアント ID とシークレットを控える。
3. **鍵を取る**（5 分。手元のパソコンで）
   ```bash
   cd yt-econ
   # .env に 2 行足す
   #   PSY_YOUTUBE_CLIENT_ID=...
   #   PSY_YOUTUBE_CLIENT_SECRET=...
   python scripts/auth_youtube.py --prefix PSY_
   # ブラウザが開く → 「新しいチャンネル」のほうを選んで許可
   # 開かなければ、表示された URL を開き、最後にたどり着いた localhost の URL を丸ごと:
   python scripts/auth_youtube.py --prefix PSY_ --code "http://localhost/?code=..."
   ```
   `.env` に `PSY_YOUTUBE_REFRESH_TOKEN=` が書かれます。
4. **GitHub の Secrets に 3 つ足す**（3 分）
   Settings → Secrets and variables → Actions → New repository secret:
   `PSY_YOUTUBE_CLIENT_ID` / `PSY_YOUTUBE_CLIENT_SECRET` / `PSY_YOUTUBE_REFRESH_TOKEN`。
   （本体の 3 つはそのまま。**この 3 つが入るまで psych の自動実行は何もしません**。本体の鍵に落ちて誤投稿しない設計です）
5. **素材 zip に BGM を 1 曲足す**（5 分）
   いまの `ytecon_materials.zip` に `assets/bgm/Yair Cohen - Rise Within.mp3` を足して Drive の同じファイルを差し替える
   （無ければ本体と同じ曲で作られる。立ち絵は同じものを使うので追加なし）。
6. **試運転**（待ち時間 70 分）
   Actions → 「毎日 本編1本 + Shorts 3本を自動生成して予約投稿」→ Run workflow → `channel=psych`、`upload=false`。
   成果物 `ytecon-psych-<番号>` の `video.mp4` と `shorts/*/video.mp4` を見る。
   このチャットに貼ってくれれば、トーン・速さ・配色をここで直します。
7. **本番**
   `config/channels/psych/schedule.yaml` の日付と `goals.yaml` の `start` を初回投稿日にして main に入れる。
   翌日から 10:10 に本体と並んで動き、20:00 に本編、7:30 / 12:30 / 21:30 に Shorts が出ます。
   サムネを手で作る日は `thumbnails/psych/<公開日>.jpg` に置く。作らない日は framed スタイルで自動生成。

## 5. 手元で動かすとき

```bash
python -m ytecon --channel psych doctor        # 設定と鍵の確認（PSY_ の鍵が見えているか）
python -m ytecon --channel psych topics -n 3   # 企画だけ見る
python -m ytecon --channel psych run           # 本編 1 本 + Shorts 3 本を作って予約
python -m ytecon --channel psych goal          # 目標の進捗（config/channels/psych/goals.yaml）
python -m ytecon --channel psych publish-file ps_001_20260929.mp4 --privacy private
```

環境変数 `YTECON_CHANNEL=psych` でも同じです。作業ファイルは `output/psych/`、状態は `output/psych/state.sqlite3`、
Actions のキャッシュ名は `ytecon-psych-state-*` で、本体（`ytecon-state-*`）とは混ざりません。

## 6. 仕組み（3 チャンネル目を作るときに読む）

- `config/channels/<key>/channel.yaml` の先頭に `extends: ../../channel.yaml` と書くと本体を継承します（辞書は深くマージ、リストは置き換え）。
- 分野の言葉（`channel.field` / `lens` / `topic_words` / `term_examples` / `pitch` / `disclaimer` / `hook_examples` / `hashtags` / `generic_words`）が
  台本・企画・Shorts・概要欄のプロンプトに差し込まれます（`src/ytecon/domain.py`）。書かなければ経済の文言。
- `channel.env_prefix` を付けると鍵は `<prefix>YOUTUBE_*` を先に読みます。無いときに本体の鍵へ落ちるのは**読み取り以外では禁止**で、
  投稿しようとすると止まります（`youtube.check_channel_keys`。同じアカウントに上げたいときだけ `upload.share_main_account: true`）。
- 置き場を分けるキー: `pipeline.workdir` / `upload.thumbnail_dir` / `upload.finals_dir` / `upload.finals_prefix` / `topics.schedule_file` / `goal.file`。
- 見た目: `video.design`（`config/design_tokens.yaml` のプリセット）と `thumbnail.style`（`bar` / `framed`）、`render.bgm.file`。
- Actions は `daily-upload.yml` の `matrix.include` に 1 行足すだけ（`channel` / `workdir` / `state_key` / `token_env`）。
  テスト `tests/test_channels.py` が、matrix と `config/channels/` の一覧が一致していることを確かめます。
