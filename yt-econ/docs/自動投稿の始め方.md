# 自動投稿の始め方（GitHub Actions で毎日 本編 1 本 + Shorts 3 本）

設定はすべてブラウザで済みます。あなたのパソコンで動かすのは、鍵を作る 2 つのコマンドだけです。
設定後は毎日 JST 15:00 に GitHub のサーバーで生成が始まり、本編はその日の 19:00、Shorts は
18:00 → 翌 0:00 → 翌 12:00 に予約公開されます（`shorts.publish_times_jst`）。目標の進捗（`ytecon goal`）も毎日 Actions のサマリに出ます。

ワークフロー本体: `.github/workflows/daily-upload.yml`

---

## 1. YouTube の鍵（30 分・1 回だけ）

1. [Google Cloud Console](https://console.cloud.google.com/) でプロジェクトを作る
2. 「API とサービス」→「ライブラリ」で **YouTube Data API v3** と **YouTube Analytics API** を有効化
3. 「OAuth 同意画面」を作る（ユーザーの種類: 外部 / テストユーザーに自分の Google アカウントを追加）
4. 「認証情報」→「OAuth クライアント ID」→ アプリの種類 **デスクトップ** → クライアント ID とシークレットを控える
5. 手元のパソコンで 1 回だけ:

```bash
cd yt-econ
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # YOUTUBE_CLIENT_ID / YOUTUBE_CLIENT_SECRET を書く
python scripts/auth_youtube.py  # ブラウザが開く → 投稿するチャンネルのアカウントで許可
```

表示された **refresh token** を控える（Analytics のスコープも付いているので、総再生時間と視聴率まで取れます）。

## 2. 台本生成の鍵（5 分）

Claude のサブスクの枠で台本を書くなら、手元で:

```bash
npm install -g @anthropic-ai/claude-code
claude setup-token
```

表示されたトークンが `CLAUDE_CODE_OAUTH_TOKEN`。
サブスクではなく API で使うなら、代わりに `ANTHROPIC_API_KEY` を登録すれば自動でそちらが使われます（従量課金）。

## 3. 素材の zip（5 分）

立ち絵（坂本アヒル様の PSD）と BGM は配布元の規約で **リポジトリに入れられない**ので、
zip にして自分だけが読める場所に置き、その直リンクを Actions に渡します。

- zip の中身は `assets/` と同じ構造:
  ```
  assets/character/ずんだもん立ち絵素材2.3/ずんだもん立ち絵素材2.3.psd
  assets/character/四国めたん立ち絵素材2.1/四国めたん立ち絵素材2.1.psd
  assets/bgm/Score Maestro - Up to No Good.mp3
  ```
  （この構成の zip は `ytecon_materials.zip` として一度お渡ししています）
- 置き場所は、**直リンクで curl できる場所**ならどこでも。いちばん簡単なのは、
  GitHub のこのリポジトリ（非公開）で **Releases → Draft a new release → ファイルを添付**。
  添付ファイルの URL（`https://github.com/<owner>/<repo>/releases/download/<tag>/ytecon_materials.zip`）を
  `MATERIALS_URL` に入れます。非公開リポジトリのリリース添付は、ログイン済みブラウザからは開けても
  curl では 404 になるので、その場合は `MATERIALS_URL` に
  `https://<GitHubのトークン>@github.com/...` の形で PAT（repo 読み取り）を含めるか、
  Dropbox / Google Drive の「直接ダウンロード」リンクを使ってください。
- 背景の実写素材（Mixkit、2〜3GB）は初回の実行で自動で集めてキャッシュします。何もしなくて大丈夫です。

## 4. GitHub に登録する

リポジトリ → **Settings → Secrets and variables → Actions → New repository secret**

| 名前 | 中身 | 必須 |
|---|---|---|
| `YOUTUBE_CLIENT_ID` | 1 で作ったクライアント ID | ◎ |
| `YOUTUBE_CLIENT_SECRET` | 同シークレット | ◎ |
| `YOUTUBE_REFRESH_TOKEN` | 1 で表示された refresh token | ◎ |
| `CLAUDE_CODE_OAUTH_TOKEN` | 2 のトークン（サブスク） | どちらか |
| `ANTHROPIC_API_KEY` | API キー（従量課金） | どちらか |
| `MATERIALS_URL` | 3 の zip の直リンク | ◎（無いと仮キャラ・BGM なし） |
| `PEXELS_API_KEY` | 写真素材 | 任意 |

## 5. 試運転 → 本番

1. **Actions** タブ → 「毎日 本編1本 + Shorts 3本を自動生成して予約投稿」→ **Run workflow**
   → `upload` を **false** にして実行。60〜100 分で終わる
2. 実行結果の **Artifacts** から `video.mp4`（本編）と `shorts/short_01..03/video.mp4` を落として確認
3. 問題なければ何もしなくてよい。翌日から毎日 15:00 に動き、19:00 に本編が公開される
4. 毎朝、Actions の実行ログの **Summary** に「目標の進捗」と打ち手が出る。打ち手のとおり `config/` を直してコミットする

## 6. 費用と時間

| 項目 | 目安 |
|---|---|
| 1 日の実行時間 | 本編 50〜70 分 + Shorts 3 本 15 分 + 素材の復元 5 分 = **70〜100 分** |
| GitHub Actions 無料枠 | 非公開リポジトリは月 2,000 分 → **足りません**（30 日 × 80 分 = 2,400 分） |
| 対策 | リポジトリを **公開**にする（Actions が無制限。鍵は Secrets なので見えない。素材は zip 側なので入っていない）か、Team プラン（月 3,000 分）にする |
| YouTube API クォータ | 本編 1,600 + 字幕 400 + サムネ 50 + Shorts 1,600 × 3 = **6,850 / 10,000** |
| LLM | サブスクなら枠内。API なら 1 日 4 本ぶんで数百円 |

## 7. サムネイルを手で作る（ChatGPT など）

自動生成のサムネより、手で作った 1 枚のほうがクリック率は上がります。やり方は「置くだけ」です。

1. 画像を作る（1280×720 が理想。正方形や 1920×1080 でも自動で中央を切って整えます。png / jpg / webp）
2. `yt-econ/thumbnails/` に **公開日の名前**で置いてコミットする: `2026-09-23.jpg`（`20260923.png`、`0923.jpg` でも可）
3. その日の 15:00 の実行で自動的にそのサムネが使われる。無い日は自動生成

**すでに投稿された本編に後から付ける**（画像が間に合わなかった日）:

```bash
python -m ytecon thumbnail 画像.png --date 2026-09-23     # thumbnails/ に保存し、YouTube 側も差し替える
```

このチャットに画像を貼ってもらえれば、こちらで `thumbnails/<公開日>.jpg` に入れてコミットします。
その日の 15:00 より前に入っていれば、そのまま使われます。

## 8. 止め方・変え方

| やりたいこと | 場所 |
|---|---|
| 一時停止 | Actions タブ → ワークフロー → 「…」→ **Disable workflow** |
| 本編の公開時刻（19:00） | `config/channel.yaml` の `upload.publish_times_jst` |
| Shorts の本数・公開時刻（12:00 / 18:00 / 0:00） | `shorts.per_video` / `shorts.publish_times_jst` |
| 手で作ったサムネ | `thumbnails/<公開日>.jpg` を置く（7 節） |
| 来週の企画 | `config/schedule.yaml`（日付つきで書くとその日に使われる） |
| 生成の開始時刻 | `.github/workflows/daily-upload.yml` の `cron`（UTC 表記） |

## 9. 動かなかったら

- **VOICEVOX の起動待ちで止まる** → もう一度 Run workflow（コンテナの取得に時間がかかっただけのことが多い）
- **YouTube のアップロードで 401 / invalid_grant** → refresh token の期限切れ。OAuth 同意画面が「テスト」のままだと 7 日で切れるので、同意画面を **本番環境に公開**（審査は不要）してから `auth_youtube.py` をやり直す
- **quotaExceeded** → その日の API 上限。翌日（太平洋時間 0 時）に戻る。`shorts.per_video` を減らす
- **仮キャラ（丸い顔）で出た** → `MATERIALS_URL` が curl で落とせていない。ログの「立ち絵と BGM を展開」を見る
- それ以外は Actions のログの赤い ✕ の部分を貼ってください
