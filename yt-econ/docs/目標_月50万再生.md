# 目標: 30 日で 50 万再生 → 収益化

> 結論を先に書きます。
> **本編（1 日 1 本・16 分）だけでは 50 万再生に届きません。** 新規チャンネルの本編は
> 初月 1 本あたり数十〜数百回が実感値で、30 本で 1 万回前後です。
> **届かせる手段は Shorts です。** 本編 1 本から 3 本を自動で切り出し、1 日 3 本・月 90 本を出す。
> Shorts は新規チャンネルでも発見面（ショートフィード）に載るので、当たれば 1 本で 10 万回が出ます。
> そして **収益化（YPP）に要る「長尺の総再生時間 4,000 時間」は本編が稼ぐ**。役割を分けます。
>
> 正直に言うと、50 万は「当たり」が 2〜3 本出る前提の数字です。
> 出なければ月 5〜15 万回に落ち着きます。だから週ごとに関門を置き、
> 下回ったら同じ型を続けない仕組みを入れました（`ytecon goal`）。

---

## 1. 数字の分解

| | 1 日 | 30 日 |
|---|---|---|
| 目標 | 16,667 再生 | 500,000 再生 |
| Shorts（85%） | 14,167（3 本 → 1 本 4,700） | 425,000 |
| 本編（15%） | 2,500 | 75,000 |

Shorts 1 本 4,700 回は「平均」です。実際の分布は、ほとんどが 500〜2,000 回で、
数本が 5 万〜20 万回という形になります。**平均を上げるのではなく、当たりの本数を増やす**
のが正しい打ち手なので、本数（1 日 3 本）と型のばらつき（区間の選び方）を優先します。

### 収益化の条件との関係

| 条件 | 必要量 | 誰が稼ぐか |
|---|---|---|
| 登録者 | 1,000 人 | Shorts（発見）→ 本編（定着） |
| 長尺の総再生時間（12 ヶ月） | 4,000 時間 | 本編。16 分の 30% = 5 分見られるとして、**4.8 万回** |
| または Shorts の再生（90 日） | 1,000 万回 | 現実的ではない。上の経路で行く |

本編 4.8 万回は、目標内訳の 7.5 万回に収まっています。**50 万再生が達成できれば YPP の条件は同時に満たせる**設計です。
逆に、Shorts だけ伸びて本編が回らないと、再生は増えても収益化が遅れます。
Shorts の概要欄 1 行目に本編リンク、Shorts の締めの前に「本編は 19 時」を必ず入れているのはそのためです。

## 2. 仕組み（何が自動で回るか）

```
ytecon run                      # 1 日 1 回（15:00）
  ├ 本編 16 分 → 19:00 に予約
  └ Shorts × 3 → 18:00 / 翌 0:00 / 翌 12:00 に予約
        区間: ずんだもんの疑問・ボケ → めたんの数字入りの答え、で完結する 30〜58 秒
        画面: 上にフック見出し、中に図表・表、下に 2 人、その上に字幕（1080×1920）
        導線: 概要欄に本編リンク、#Shorts

ytecon goal                     # 1 日 1 回（朝）
  ├ 再生・登録者・総再生時間・動画別の視聴率を取る（Analytics → 無ければ公開統計）
  ├ 必要ペース・予測・関門の合否を出す
  └ 打ち手を出す（設定のどこを動かすかまで）
```

| ファイル | 役割 |
|---|---|
| `config/goals.yaml` | 目標・関門・1 本ごとの合否ライン |
| `config/channel.yaml` の `shorts:` | 本数・尺・投稿時刻・縦画面の組み方 |
| `src/ytecon/shorts.py` | 区間の選定・縦画面の書き出し・メタデータ |
| `src/ytecon/goals.py` | 数字の取得・ペース計算・打ち手 |
| `output/goal/snapshots.jsonl` | 毎日の記録（日別の伸びの復元にも使う） |

### Shorts の作り方（story モード）

Shorts は本編の切り出しではありません。切り出しは途中から始まって途中で終わるので、
指を止めた人にも何の話か分からず、最後まで見られませんでした。
いまは本編の台本を材料に、LLM が 1 本ごとに次の型で 45〜55 秒を書き直し、音声も新しく合成します。

| ビート | 秒 | 中身 | 画面 |
|---|---|---|---|
| 起 | 0〜6 | ずんだもんの具体的な状況か、意外な数字。前置きなし | 一句カード / 数字 |
| 承 | 6〜20 | めたんが数字と出典で事実を言う | 数字 / 表 |
| 転 | 20〜40 | ずんだもんが極端な結論に飛び、めたんが「むしろ」で返す（山場） | 比較 / 一句 |
| 結 | 40〜50 | 今夜できる 1 つの行動、または覚えて帰る 1 つの数字 | 手順 / 一句 |
| 誘導 | 50〜56 | 「続きは本編で聞くのだ」「本編は毎日19時、下のリンクから」（`shorts.cta`） | 「続きは本編で」カード |

数字と社名は本編の台本にあるものしか使わせません（新しい統計を作らせない）。
1 年以上前の統計は「令和6年の時点で」と時点を言い、「今は変わっているが出だしで差があった」として使います。
「下のリンク」は Shorts の関連動画リンクのことで、API からは付けられません。公開後に YouTube Studio →
その Shorts → 「関連動画」で本編を選んでください（Shorts で概要欄を開く人はほぼいないため）。
声は本編より少し速く（1.25 倍、間 0.22 秒）。LLM が使えない日は、下の「区間の切り出し」に落ちます。

### 区間の選び方（cut モードの点数）

| 加点 | 減点 |
|---|---|
| 聞き役（ずんだもん）の一言から始まる +2 | 出だしが前の発言を受けている（でも／それで／つまり）−3 |
| 疑問で始まる +2.5 | 出だしが直前の数字へのリアクション（5 倍くらい違うのだ）−4 |
| セクションの頭から +1 | 答えで終わっていない −1 |
| 聞き役のリアクション（驚・困・笑）1 つ +1.5（3 まで） | 45 秒から離れるほど −（差 ÷ 12） |
| 数字入りの文 1 つ +1（4 まで） | |
| 視点の切り替え（実は／むしろ／早とちり）+1.5（2 まで） | |
| 掛け合い 2 往復以上 +1.5 | |

締め（closing）は切り出しません。本編を見る理由を残すためです。
`ytecon shorts <slug> --list` で候補と点数の理由が見られます。重みは `shorts.py` の `score_window`。

## 3. 週ごとの関門と、下回ったときの打ち手

| 日 | 再生（累計） | 登録者 | 下回ったら |
|---|---|---|---|
| 7 | 20,000 | 100 | Shorts を 1 日 4 本に（`shorts.per_video: 4`）。区間を 45 秒以下に（`shorts.max_seconds: 45`） |
| 14 | 80,000 | 300 | 直近で視聴率が最も高かった Shorts の型（出だし・長さ・テーマ）に寄せる。当たったテーマの派生を `schedule.yaml` に 2 本 |
| 21 | 220,000 | 600 | 本編のサムネ・タイトルを全部見直す（`ytecon revive --apply`）。Shorts の見出しを疑問形に統一 |
| 30 | 500,000 | 1,000 | 到達なら YPP 申請。未達なら 2 ヶ月目の目標を実績 × 2 に置き直す |

上回っているときは **何も変えない**。伸びているときに設定を触るのが一番の失敗です。

### 1 本ごとの合否ライン（`goals.yaml` の `rules`）

| 種類 | 見る数字 | ライン | 下回ったら |
|---|---|---|---|
| 本編 | 公開 7 日の再生 | 300 | サムネとタイトルを作り直す |
| 本編 | 平均視聴率 | 30% | 次回から hook を 1 文短く。冒頭の「今日はここを解く」を早める |
| Shorts | 平均視聴率 | 75% | 区間を短く、出だしを疑問文に限定 |
| Shorts | 公開 3 日の再生 | 500 | 見出しを数字入りに（`shorts.llm_hooks: true`） |

## 4. API で取れない数字（週 1 回、Studio で見る）

| 数字 | 場所 | ライン | 打ち手 |
|---|---|---|---|
| 本編のインプレッションのクリック率 | アナリティクス → リーチ | 4% 未満 | サムネの文言を変える（`thumbnail_copy`） |
| 本編の最初の 30 秒の離脱 | 視聴者維持率 | 急落 | hook をずんだもんの困りごと 1 文から始める（いまの型） |
| Shorts の「視聴 vs スワイプ」 | Shorts のアナリティクス | 70% 未満 | 最初の 1 秒に見出しと声を同時に出す（いまの型。フック見出しは全編表示） |
| 登録者の増えた動画 | 視聴者 | — | そのテーマの派生を 3 本 |

`ytecon goal` の打ち手はこれらを見ていないので、Studio の数字を見た結果は
`config/channel.yaml`（トーン・尺）と `config/schedule.yaml`（企画）に手で反映します。

## 5. 収益化の申請までに整えておくこと

- **再利用コンテンツの審査対策**は本編で担保する（図表・出典・ファクトチェック・重複排除）。Shorts は本編の切り出しなので、本編が通れば Shorts も同じ扱い
- 概要欄の音声クレジットは出演者全員ぶん（VOICEVOX：四国めたん / ずんだもん）。立ち絵のクレジットも自動で入る
- 1,000 人 + 4,000 時間に届いたら **その日のうちに申請**する。審査は数日〜1 ヶ月
- 申請前に 1 日 5 分だけ、公開済みの本編の冒頭を人が見る（事実の誤りが無いか）。これが「独自性」の証跡になる

## 6. 毎日の手順（人がやるのは 2 分）

```bash
# 朝: 昨日の数字と打ち手を見る（output/goal/ に記録が残る）
python -m ytecon goal

# 夕方: 自動（cron / Actions）。本編 1 本 + Shorts 3 本を予約
python -m ytecon run

# 週 1 回: Studio の 4 つの数字を見て、schedule.yaml に来週の企画を入れる
```

打ち手に「設定のどこを動かすか」が書いてあるので、そのとおりに `config/` を直してコミットするだけです。
